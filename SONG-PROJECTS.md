# Проєкти пісень

Перший сценарій: збережений напрям → задум → пакет текстів → перевірка повторів → підтвердження власника.

## Налаштування

У Render → Environment додайте `OPENAI_API_KEY`. Це ключ API OpenAI з окремим API-балансом; підписка на ChatGPT не замінює його. Ключ не вставляють у сайт, Git або чат. Після збереження та розгортання відкрийте кабінет → «Проєкти пісень».

Необов'язкові змінні:

- `SONG_TEXT_MODEL`: початкове значення `gpt-4.1-mini`, модель можна змінити.
- `SONG_DAILY_LIMIT`: до 10 запусків за останні 24 години за замовчуванням. Значення 1–100. Це обмеження кількості запитів, а не гарантований бюджет у валюті. Встановіть також обмеження витрат у провайдера.

Для першого етапу є адаптер OpenAI Responses API. Інші провайдери ще не підключені. Збереження стилів і проєктів працює без ключа. Без ключа кнопка генерації недоступна, готові результати не підміняються демонстраційними.

## Як користуватися

1. Відкрийте «Мої стилі» — головний каталог `/songs#styles`. Можна знайти стиль за назвою, створити новий або зробити незалежну копію. Початкові Pirate і Viking не перезаписуються під час запуску сервера.
2. У редакторі є три вкладки: «Тематика», «Звучання», «Обкладинка». Налаштування можна писати українською. Незбережені зміни захищені попередженням перед виходом; одночасне редагування в іншій вкладці не перезапише новішу версію.
3. Натисніть «Створити пісню» на картці або «Зберегти й створити пісню» в редакторі. Стиль підставиться автоматично. Назву та задум можна не вводити — система підготує робочу назву й завдання придумати нову історію. Якщо генератор підключений, кнопка «Згенерувати текст» зберігає проєкт і запускає один платний запит. Без ключа є тільки «Зберегти задум», без генерації. Результат містить англійський текст, сюжет, опис для Suno та завдання для обкладинки; аудіо й зображення ще не створюються.
4. Перегляньте перевірку повторів та текст. Затвердіть або відхиліть версію. Попередні версії, включно з відхиленими, залишаються в Neon.
5. У результаті перемикайте вкладки «Слова пісні», «Для Suno», «Для обкладинки» — кожна має власну кнопку копіювання. Пісні зібрані в «Мої пісні» (`/songs#projects`). Затвердження нічого не публікує. Відхиливши затверджену версію, можна знову генерувати варіанти.

## Збереження та захист повторів

У Neon зберігаються проєкти, профілі, версії текстів, результат перевірки, запуски, модель, використані токени та точні налаштування кожного запуску. Готові тексти не залежать від тимчасового диска Render. Для вже запущеної генерації редагування стилю нічого не змінює.

Усі збережені версії перевіряються порціями: нормалізований точний збіг, збіг назви, перекриття чотирислівних фрагментів у тексті та приспівах. Пороги — 55% для тексту та 65% для приспіву. Процент означає збіг фрагментів, а не ймовірність плагіату. Це не семантичний пошук і не перевірка всіх пісень в інтернеті. Збіг блокує затвердження; для розвитку перевірки можна додати embeddings і ручне розв'язання помилкових збігів.

Генератор отримує профіль, задум і назви/сюжети до 30 останніх версій для урізноманітнення. Для відповіді використовується `store: false`. Власні записи в Neon зберігаються окремо.

Одночасно працює один запуск на всю студію. Ключ повторного запиту зберігається у браузері й має унікальне обмеження в Neon. Повтор із тим самим ключем повертає наявну спробу, а не викликає модель знову. Автоматичних повторів платних викликів немає. Втрата відповіді або перезапуск сервера можуть залишити стан «Потрібна увага»; запит міг уже бути оплачений. Запуски, що залишилися незавершеними довше 5 хвилин, позначаються так при наступному читанні/запуску. Окремо встановлений таймаут зовнішнього запиту — 90 секунд.

## Межі першого етапу

Тут немає постійного фонового планувальника, n8n, автоматичної генерації картинки, доступу до Suno API або автопублікації. Наступні етапи мають використовувати ці ж проєкти й стани, а не окремі незв'язані форми.

Міграції автоматично виконуються при запуску API. Існуючі таблиці YouTube й авторизації не змінюються. Доступ до всіх маршрутів проєктів вимагає сесії власника з другим фактором.

## Перевірки

Тести `songs.test.ts` використовують ізольований PostgreSQL через PGlite та підставлені відповіді провайдера: справжні SQL-міграції, збереження, одноразове завершення, повтори, блокування затвердження, ліміти, стан після переривання, перевірка доступу. Вони не надсилають платних запитів. Живу генерацію потрібно перевірити після додавання ключа.
