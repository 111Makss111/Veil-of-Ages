# Власний n8n для фабрики

Це окремий Docker-сервіс n8n Community, без n8n Cloud trial.
Підготовлено до розгортання, але не розгорнуто. Контейнер не запускає FFmpeg.
Сценарії, користувачі та credentials зберігаються у PostgreSQL; сталий ключ
N8N_ENCRYPTION_KEY потрібен для розшифрування credentials після redeploy.

## Перший запуск

1. У Neon створити окрему базу `n8n` та окремого власника цієї бази.
   Не використовувати користувача або базу фабрики. Взяти direct connection,
   розкласти її на host, database, user, password (без копіювання секретів у чат).
2. Після публікації цих файлів у GitHub: Render → New → Blueprint → цей репозиторій.
   Blueprint Path: `infra/n8n/render.yaml`. Перевірити, що створюється лише n8n.
3. Ввести чотири DB_POSTGRESDB_* значення. Ключ шифрування Blueprint створює сам.
   Зберегти його в менеджері паролів і надалі не замінювати.
4. Після deploy відразу відкрити URL сервісу, створити owner-акаунт n8n та
   увімкнути 2FA. До створення власника не поширювати URL.
5. Створити тестовий workflow, зробити redeploy, перевірити що workflow і вхід збереглися.
6. Settings → n8n API: створити API key. У Render **сервісу фабрики** додати
   N8N_URL (HTTPS-адреса нового n8n) та N8N_API_KEY. Наявна перевірка інтеграцій
   підтвердить API-доступ. Це ще не означає, що виробничий workflow підключений.

За ручного створення Web Service використати Root Directory `infra/n8n`,
Dockerfile `./Dockerfile`, порт 5678 та ті самі змінні. N8N_ENCRYPTION_KEY
потрібно згенерувати самому (не менше 32 випадкових символів).
RENDER_EXTERNAL_URL автоматично задає правильні editor/webhook URL.

## Межі та наступний етап

Free Render засинає після простою: таймери, черги та розклад не гарантовані.
Це лише ручний пілот. Для безперервної роботи потрібно погодити платний compute.
Не створюємо Render Free Postgres з обмеженим строком дії; використовуємо Neon.
Ліміти й оплата Neon, Render та AI API залишаються окремими.
Великі MP3/MP4 зберігаємо в R2; не в локальній файловій системі n8n.
Експортувати workflow після змін; резервувати базу разом із ключем шифрування.

ШІ-режисер ще не підключений: потрібен вибір API-провайдера та credential.
Наступна інтеграція: автентифікований запуск → план сцени у строгому JSON →
перевірка дозволених ефектів фабрикою → короткий рендер → ручний перегляд.
Поточні owner-сесії та Authenticator не передаємо n8n; сервісний доступ має
бути окремим, обмеженим лише потрібними операціями. ШІ не генерує shell-команди.
