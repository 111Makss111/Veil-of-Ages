# Фабрика Veil of Ages

## Що вже реалізовано

Після входу відкривається `/factory`: Фабрика, Музична бібліотека, Випуски, Налаштування. Старі інструменти залишаються в архіві налаштувань; дані не видалено.

Один канал, Dark Fantasy / Medieval Ambient. Рецепт обирає треки «Без вокалу» або «Хор / вокал без слів». Це позначка при завантаженні, не автоматичне розпізнавання й не перетворення аудіо. Треки передаються партією, послідовно; SHA-256 захищає від повторного збереження тих самих байтів.

Перший сценарій: наступний невикористаний трек потрібного режиму → унікальна концепція й AI-образ (або резервна ручна картинка) → cinematic MP4 16:9 → перевірка власника → приватне завантаження YouTube. Трек резервується транзакційно й використовується лише в одному випуску. Повтор невдалого складання використовує той самий трек, prompt і seed. Кожний випуск має знімок рецепта. Нічого не видаляється автоматично; власник може безпечно очищати окремі матеріали або весь тестовий випуск через інтерфейс.

## Автоматичний образ і cinematic-монтаж

Якщо в Render задано `CLOUDFLARE_AI_TOKEN`, фабрика створює окрему картинку 16:9 для кожного треку через Cloudflare Workers AI (`FLUX.2 klein 4B`). `CLOUDFLARE_ACCOUNT_ID` необов'язковий: за замовчуванням використовується `R2_ACCOUNT_ID`. R2 S3 credentials і Workers AI token мають бути різними ключами з різними правами.

Концепція, назва, prompt і seed фіксуються у випуску до зовнішнього запиту. Попередні concept hash перевіряються в Neon. Згенерований оригінал зберігається у приватному R2. Ручна картинка в рецепті є лише аварійним резервом, коли Workers AI вимкнено.

Рендерер автоматично застосовує адаптивний zoom/pan на всю тривалість треку, окремий виразний рухомий шар туману, Dark Fantasy color grade, м'яке мерехтіння освітлення, vignette, зерно, fade-in/fade-out і нормалізацію гучності. Туман розраховується у зменшеній роздільності й масштабується для композиції, кодування використовує до двох потоків і швидкий профіль — це зберігає атмосферу без попереднього надмірного навантаження Render. Доступні `auto`, `ancient-mist`, `ember-glow`, `moonlit-ruins`; `auto` враховує тему партії й стабільно розподіляє інші треки між пресетами.

Кожний випуск зберігає в Neon поточний етап, загальний відсоток, пояснення, час початку й останній heartbeat. Під час FFmpeg відсоток походить із реально обробленої тривалості, а прогноз залишку — з фактичного співвідношення змонтованих секунд до витраченого часу, а не з декоративного таймера. Інтерфейс опитує активний випуск кожні три секунди та показує матеріали → образ → монтаж → перевірку → сховище. Безпечна категорія помилки також зберігається й потрапляє в журнал Render без шляхів до файлів та секретів.

## Підключення R2

1. У Cloudflare активуйте R2. Перед підтвердженням перегляньте умови оплати: безкоштовний обсяг не є жорстким блокуванням витрат.
2. Створіть **окремий приватний bucket** класу **Standard**, наприклад `veil-of-ages-factory`. Не підключайте public development URL, публічний домен або правила автоматичного видалення. Поточний адаптер використовує стандартний endpoint акаунта, не jurisdiction-specific EU/FedRAMP endpoint.
3. Створіть S3 API credentials із дозволом читати/записувати об’єкти **тільки цього bucket**. Видалення потрібне для керованого очищення через приватний кабінет. Наш код не створює bucket і не змінює його публічність.
4. Render → сервіс API → Environment: додайте `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Це серверні змінні, без `NEXT_PUBLIC_`. Не передавайте ключі в чат, Git або браузерну форму сайту.
5. Після розгортання відкрийте Фабрика → «Перевірити місце». Сам факт наявності змінних не означає успішне підключення; кнопка читає фактичний список об’єктів.
6. Для автоматичних образів окремо створіть Workers AI API token і додайте в Render як `CLOUDFLARE_AI_TOKEN`. Не розширюйте права R2-ключа.
7. Завантажте невелику партію MP3/WAV і запустіть один випуск. Ручну обкладинку додавайте лише як резерв.

Офіційні інструкції: https://developers.cloudflare.com/r2/get-started/s3/ та https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/

## Ліміт та індикатор

Ліміт фабрики — **8 000 000 000 байтів**, не GiB. Нові аудіо й обкладинки приймаються, доки сумарна зайнятість bucket із резервами не перевищить 6 ГБ. Таким чином до 2 ГБ усередині ліміту залишаються для результатів. Для кожного відео перед початком резервується максимально можливий розмір (47 МіБ), а для AI-картинки — 8 МіБ; після збереження враховується фактичний розмір.

Перед резервуванням під блокуванням PostgreSQL сканується весь bucket з пагінацією та додаються незавершені резерви. Помилка R2 блокує запис, а не перетворює обсяг на нуль. Якщо R2 прийняв файл, але відповідь або запис у базі втрачено, резерв зберігається: можливий консервативний подвійний підрахунок. Не знімайте його вручну без перевірки об’єкта. Поки автоматичної процедури звіряння таких записів немає.

Індикатор оновлюється при відкритті, після партії та кнопкою; не робить постійних запитів R2. Це **не ліміт рахунка Cloudflare**: сторонні завантаження, інші bucket, операції API й інші сервіси можуть оплачуватись окремо. Не використовуйте цей bucket для інших застосунків. Резерви в базі та файли мають залишатися синхронними; не очищуйте таблиці фабрики окремо від сховища.

## Межі першого сценарію

- MP3/WAV до 25 МіБ, 1–300 секунд; PNG/JPG до 8 МіБ. Рендер перевіряє розміри зображення, тривалість і результуючий MP4.
- Одна композиція = одне звичайне відео, не багатогодинна ambient-збірка. Shorts залишились у ручному інструменті.
- Автоматичної генерації музики, LLM-описів, розкладу, n8n та Telegram-запуску ще немає. Картинка й назва генеруються автоматично, коли підключено Workers AI; під час передачі використовується чинний тестовий опис YouTube. Публічного постингу немає.
- Поточний worker живе в API: закриття сторінки не зупиняє його, але сон/перезапуск сервера може перервати роботу. Для тестування на `0.1 CPU` FFmpeg має 90-хвилинний аварійний ліміт; активний прогрес оновлює heartbeat, а через 30 хвилин без жодного оновлення випуск позначається перерваним. Кнопка повтору не бере новий трек. Для цілодобового виконання потрібен наступний етап з worker/n8n на відповідному хостингу.
- Після невідомого результату YouTube автоматичний повтор заборонений. Перевіряйте Studio. Це запобігає дублюванню, але поки потребує ручної звірки.
- Бібліотека має окремі вкладки музики, картинок і відео та показує останні 300 матеріалів; випуски — останні 100. Матеріал, пов’язаний із випуском або рецептом, окремо видалити не можна. Видалення випуску прибирає його MP4 та автоматично створену картинку, але зберігає оригінальну музику й не видаляє вже передане приватне відео з YouTube.

## Перевірки

`factory.test.ts`: ізольована PostgreSQL (PGlite), підставлене об’єктне сховище, тестове складання й імітація передачі. Перевіряються доступ/Origin, збереження, обмеження місця, дублікати, резервування, повтор на тих самих матеріалах, підтвердження прав і блокування повторної передачі. Жодних реальних R2/YouTube-записів чи платних генерацій у тестах немає.
