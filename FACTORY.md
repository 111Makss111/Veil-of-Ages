# Фабрика Veil of Ages

## Що вже реалізовано

Після входу відкривається `/factory`: Фабрика, Музична бібліотека, Випуски, Налаштування. Старі інструменти залишаються в архіві налаштувань; дані не видалено.

Один канал, Dark Fantasy / Medieval Ambient. Рецепт обирає треки «Без вокалу» або «Хор / вокал без слів». Це позначка при завантаженні, не автоматичне розпізнавання й не перетворення аудіо. Треки передаються партією, послідовно; SHA-256 захищає від повторного збереження тих самих байтів.

Перший сценарій: наступний невикористаний трек потрібного режиму → збережена обкладинка → MP4 16:9 → перевірка власника → приватне завантаження YouTube. Трек резервується транзакційно й використовується лише в одному випуску. Повтор невдалого складання використовує ті самі матеріали. Кожний випуск має знімок рецепта. Ні оригінали, ні результати автоматично не видаляються.

## Підключення R2

1. У Cloudflare активуйте R2. Перед підтвердженням перегляньте умови оплати: безкоштовний обсяг не є жорстким блокуванням витрат.
2. Створіть **окремий приватний bucket** класу **Standard**, наприклад `veil-of-ages-factory`. Не підключайте public development URL, публічний домен або правила автоматичного видалення. Поточний адаптер використовує стандартний endpoint акаунта, не jurisdiction-specific EU/FedRAMP endpoint.
3. Створіть S3 API credentials із дозволом читати/записувати об’єкти **тільки цього bucket**. Наш код не створює bucket, не змінює його публічність і не має операцій видалення.
4. Render → сервіс API → Environment: додайте `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Це серверні змінні, без `NEXT_PUBLIC_`. Не передавайте ключі в чат, Git або браузерну форму сайту.
5. Після розгортання відкрийте Фабрика → «Перевірити місце». Сам факт наявності змінних не означає успішне підключення; кнопка читає фактичний список об’єктів.
6. Завантажте невелику партію MP3/WAV, потім обкладинку. Оберіть її в рецепті, збережіть і запустіть один випуск.

Офіційні інструкції: https://developers.cloudflare.com/r2/get-started/s3/ та https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/

## Ліміт та індикатор

Ліміт фабрики — **8 000 000 000 байтів**, не GiB. Нові аудіо й обкладинки приймаються, доки сумарна зайнятість bucket із резервами не перевищить 6 ГБ. Таким чином до 2 ГБ усередині ліміту залишаються для результатів. Для кожного відео перед початком резервується максимально можливий розмір (24 МіБ), після збереження враховується фактичний.

Перед резервуванням під блокуванням PostgreSQL сканується весь bucket з пагінацією та додаються незавершені резерви. Помилка R2 блокує запис, а не перетворює обсяг на нуль. Якщо R2 прийняв файл, але відповідь або запис у базі втрачено, резерв зберігається: можливий консервативний подвійний підрахунок. Не знімайте його вручну без перевірки об’єкта. Поки автоматичної процедури звіряння таких записів немає.

Індикатор оновлюється при відкритті, після партії та кнопкою; не робить постійних запитів R2. Це **не ліміт рахунка Cloudflare**: сторонні завантаження, інші bucket, операції API й інші сервіси можуть оплачуватись окремо. Не використовуйте цей bucket для інших застосунків. Резерви в базі та файли мають залишатися синхронними; не очищуйте таблиці фабрики окремо від сховища.

## Межі першого сценарію

- MP3/WAV до 25 МіБ, 1–300 секунд; PNG/JPG до 8 МіБ. Рендер перевіряє розміри зображення, тривалість і результуючий MP4.
- Одна композиція = одне звичайне відео, не багатогодинна ambient-збірка. Shorts залишились у ручному інструменті.
- Автоматичних генерацій музики/картинки, LLM-описів, розкладу, n8n та Telegram-запуску ще немає. Назва випуску формується з назви треку; під час передачі використовується чинний тестовий опис YouTube. Публічного постингу немає.
- Поточний worker живе в API: закриття сторінки не зупиняє його, але сон/перезапуск сервера може перервати роботу. Через 30 хвилин без завершення випуск позначається невдалим при наступному читанні. Кнопка повтору не бере новий трек. Для цілодобового виконання потрібен наступний етап з worker/n8n на відповідному хостингу.
- Після невідомого результату YouTube автоматичний повтор заборонений. Перевіряйте Studio. Це запобігає дублюванню, але поки потребує ручної звірки.
- Список показує останні 200 вхідних матеріалів та 100 випусків; записи поза списком не видаляються.

## Перевірки

`factory.test.ts`: ізольована PostgreSQL (PGlite), підставлене об’єктне сховище, тестове складання й імітація передачі. Перевіряються доступ/Origin, збереження, обмеження місця, дублікати, резервування, повтор на тих самих матеріалах, підтвердження прав і блокування повторної передачі. Жодних реальних R2/YouTube-записів чи платних генерацій у тестах немає.
